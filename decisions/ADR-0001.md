# ADR-0001: Use PostgreSQL for both evidence and graph storage in MVP
Status: accepted for initial build.

Context: relationships are case-scoped and need strong provenance, revisioning and relational integrity. Specialized graph DB would add operational overhead and dual-write consistency risks.

Decision: store entities and edges in PostgreSQL tables; traverse with indexed adjacency queries/recursive CTEs; visualize with React Flow; benchmark representative 300-node/500-edge fixtures. Add graph DB only if proven workloads exceed PostgreSQL capacity or query ergonomics become material.

Consequences: simpler backups/transactions/security. Requires explicit recursive query depth cap and performance monitoring. Graph-specific analytics may be a later service.
