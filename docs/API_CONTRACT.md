# HTTP API contract (proposed v1)

Base path `/api/v1`; authenticated production requests use secure session/token, CSRF protections as applicable. JSON response envelopes; typed OpenAPI schema generated by FastAPI and TS client codegen. Case endpoints require both workspace membership and case access. IDs are UUID; examples use placeholders. Every list response has `{items,next_cursor}`.

## 1. Endpoints
| Method | Path | Description |
|---|---|---|
| GET / POST | `/workspaces` | List/create permitted workspaces |
| GET / POST | `/cases` | List/create cases |
| GET / PATCH / DELETE | `/cases/{case_id}` | Read/update/archive (DELETE archives) |
| GET | `/cases/{case_id}/overview` | Stats and recent events |
| GET | `/cases/{case_id}/entities` | Paginated case entities |
| POST | `/cases/{case_id}/entities` | Propose/curate entity |
| GET | `/cases/{case_id}/graph` | Node/edge subgraph with filters and capped depth |
| POST | `/cases/{case_id}/relationships` | Propose relation; not auto-approve |
| GET / POST | `/cases/{case_id}/sources` | Paginated evidence / add permitted source record |
| GET | `/cases/{case_id}/sources/{source_id}` | Source provenance and observations |
| POST | `/cases/{case_id}/reviews` | Approve/dispute/reject with reason |
| GET | `/cases/{case_id}/reviews/pending` | Pending review queue |
| POST | `/cases/{case_id}/research/plans` | Generate bounded plan, no external requests |
| POST | `/cases/{case_id}/research/runs` | Execute an explicitly approved plan |
| GET | `/cases/{case_id}/research/runs/{run_id}` | Progress and step state |
| POST | `/cases/{case_id}/research/runs/{run_id}/cancel` | Idempotent cancel request |
| GET | `/cases/{case_id}/research/runs/{run_id}/events` | SSE updates |
| POST | `/cases/{case_id}/ai/answers` | Cite grounded evidence for one case |
| GET / POST | `/cases/{case_id}/reports` | List/create report drafts |
| POST | `/cases/{case_id}/reports/{report_id}/exports` | Export reviewed report |
| GET | `/connectors` | Available integrations, permissions, health |
| PATCH | `/connectors/{id}` | Enabled/disabled, terms policy; admin only |
| GET | `/audit-events` | Workspace admin audit feed |
| GET | `/health/live` and `/health/ready` | Process liveness/dependency readiness |

## 2. Example request: case
```json
{
  "title": "Aurora Systems public research",
  "purpose": "Study a fictional organization's publicly documented technology footprint",
  "scope": {
    "subjects": [{"type": "organization", "value": "Aurora Systems"}, {"type": "domain", "value": "aurora.example"}],
    "connectors": ["manual", "public_rss"],
    "expires_at": "2027-01-15T00:00:00Z",
    "max_requests_per_run": 30
  }
}
```
Demo requests must stay fixture-only; `.example` domains are never fetched over network.

## 3. Example response: graph
```json
{
  "case_id": "00000000-0000-4000-8000-000000000001",
  "nodes": [{"id": "entity-1", "type": "organization", "label": "Aurora Systems", "review_status": "approved", "demo": true}],
  "edges": [{"id": "relation-1", "source": "entity-1", "target": "entity-2", "type": "publishes", "review_status": "approved", "evidence_ids": ["observation-9"], "demo": true}],
  "truncated": false,
  "next_cursor": null
}
```
The sample is schematic; API implementers must use valid UUIDs in actual typed fixtures and provide referenced nodes in complete graph payloads.

## 4. Research plan proposal
```json
{
  "objective": "Summarize documented public announcements for Aurora Systems",
  "candidate_steps": [
    {"connector": "public_rss", "subject_id": "entity-1", "action": "search_approved_feed", "max_items": 10}
  ],
  "policy_validation": "pending_user_approval",
  "estimated_external_requests": 1
}
```
Execution endpoint accepts immutable `plan_id` + user confirmation and idempotency key, never an arbitrary list of HTTP destinations from model output.

## 5. AI grounded answer
```json
{
  "answer": "The provided evidence documents two public announcements.",
  "claims": [
    {"text": "The case has two sourced announcements.", "observation_ids": ["observation-1", "observation-2"], "support": "supported"}
  ],
  "unknowns": ["The evidence does not establish ownership of the external domain."],
  "proposed_relationship_ids": [],
  "validation": {"missing_source_ids": [], "schema_valid": true}
}
```
Claims referencing nonexistent/forbidden observation IDs are rejected server side. The answer is advisory, not evidence itself.

## 6. SSE event names
`run.queued`, `step.started`, `step.completed`, `step.failed`, `run.cancel_requested`, `run.completed`, `run.failed`. Payload always `{event_id,run_id,step_id?,timestamp,source?,count?,message?}` with no raw secrets.

## 7. Errors, scopes and rate limits
Error envelope `{error:{code,message,request_id,details?}}`. Codes: `VALIDATION_ERROR`, `NOT_FOUND`, `FORBIDDEN`, `SCOPE_NOT_APPROVED`, `PROVIDER_RATE_LIMIT`, `SOURCE_TERMS_DENIED`, `PRIVATE_ADDRESS_BLOCKED`, `CONNECTOR_UNAVAILABLE`, `BUDGET_EXCEEDED`, `CONFLICT`, `UNSUPPORTED_CONTENT`. Use `409` for conflicting edits, `422` for invalid input, `429` for rate limits; return `Retry-After` when known. Opaque missing-case responses should not reveal existence outside user's workspace. Cursor-based pagination, tenant quotas and API schema tests mandatory.
